## 1. 目的

本書は、WebタイムカプセルのMVPにおけるフロントエンドの画面、操作、状態、入力制約、写真認証、バックエンドとの責務境界を定義する。

本書で定義する「写真認証」は本人確認や顔認証ではない。フォルダ作成時に登録した鍵写真と、現在撮影した写真について、人数、立ち位置、ポーズが近いかを判定する体験を指す。

## 2. プロダクト概要

参加者で写真を保存する共有フォルダを作り、フォルダを開くたびに、鍵写真の構図とポーズを再現して楽しむスマートフォン向けWebアプリである。

### 2.1 MVPの基本方針

- 通常のログインにはGoogleアカウントを使用する。
- フォルダ単位で参加者と鍵写真を登録する。
- フォルダを開くには写真認証を行う。
- 写真認証の試行回数に上限は設けない。
- 認証成功後は同じ閲覧セッション内で再認証を求めない。
- フォルダの中には写真だけを保存する。テキストメッセージは扱わない。
- 開封日、カウントダウン、予定日時の通知は設けない。
- メンバー招待・承認フローはMVPに含めない。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| フォルダ | 参加者、鍵写真、保存写真をまとめる共有単位 |
| 参加者 | フォルダ作成時にメールアドレスを登録されたユーザー。作成者を含む |
| 鍵写真 | フォルダ作成時に1枚だけ登録し、写真認証の基準にする写真 |
| 保存写真 | 認証後のフォルダ内で参加者がアップロード・閲覧・削除する写真 |
| 認証用写真 | フォルダを開くため、その場でカメラ撮影する写真。保存写真には自動追加しない |
| 写真認証 | 鍵写真と認証用写真の人数、並び順、ポーズを比較する処理 |
| 認証セッション | 写真認証の成功後、そのフォルダを閲覧できる最長12時間の状態 |
| 署名付きURL | 非公開ストレージ上の写真に、短時間だけアクセスできるURL |

「認証アルバム」は設けない。1フォルダにつき鍵写真は1枚のみで、認証用写真の履歴も保存しない。

## 4. MVPの範囲

### 4.1 対象機能

- Googleログイン、ログアウト
- 参加中フォルダの一覧表示
- フォルダ作成
- 鍵写真の選択と登録可否チェック
- 写真認証
- 保存写真の一覧、詳細表示
- 保存写真のアップロード、複数選択削除
- フォルダ情報の表示
- フォルダ全体の削除

### 4.2 MVP対象外

- 開封日、公開予約、カウントダウン
- メール、プッシュなどの通知
- 招待リンク、招待の承認・拒否
- 作成後の参加者追加・削除
- フォルダ名の変更
- 鍵写真の変更
- 顔認証、本人確認
- 認証用写真の履歴・アルバム
- テキストメッセージ
- 5人以上での写真認証
- 複数端末間での認証セッション共有
- ネイティブアプリ

## 5. アカウントと参加者

### 5.1 ログイン

- Googleログインを必須とする。
- ログイン後のメールアドレスはGoogleで確認済みのものを使用する。
- 未ログイン時に認証必須画面へアクセスした場合はログイン画面へ遷移し、成功後に遷移元へ戻す。
- ログアウト時は端末内にある全フォルダの認証セッションを破棄する。

### 5.2 参加者登録

- フォルダ作成者は自動的に参加者へ含める。
- 作成画面で、作成者以外の参加者のGoogleメールアドレスを入力する。
- 参加者数は作成者を含めて2〜4人とする。
- 同じメールアドレスを重複登録できない。
- 作成時点で相手が本サービスへログイン済みでなくてもメールアドレスを登録できる。
- 後から、そのメールアドレスでGoogleログインしたユーザーのフォルダ一覧に対象フォルダを表示する。
- フォルダ作成後、参加者は変更できない。

### 5.3 権限

参加者全員が同じ権限を持つ。作成者専用の管理権限は設けない。

| 操作 | 参加者 | 非参加者 |
| --- | --- | --- |
| フォルダ一覧への表示 | 可 | 不可 |
| 写真認証 | 可 | 不可 |
| 保存写真の閲覧 | 認証成功後に可 | 不可 |
| 保存写真のアップロード | 認証成功後に可 | 不可 |
| 保存写真の削除 | 認証成功後に可 | 不可 |
| フォルダ全体の削除 | 認証成功後に可 | 不可 |

表示制御だけに依存せず、すべての操作についてバックエンドでも参加者であることを検証する。

## 7. 画面遷移

~~~text
S01 ログイン

       ├─ 新規作成 → S03 → S04 → S05 → S06 → S02
       └─ フォルダ選択
            ├─ 有効な認証セッションあり → S12 写真一覧
            └─ 未認証 → S07 → S08 → S09 → S10
                                      ├─ 成功 → S11 → S12
                                      └─ 失敗 → S11 → S09

S12 写真一覧
  ├─ 写真選択 → S14
  ├─ 写真追加 → S15
  ├─ 写真表示 → S13
~~~

ブラウザ更新時は現在のURLと認証セッションから画面を復元する。認証成功済みであれば、更新だけを理由にS07へ戻さない。

## 8. 各画面の仕様

### 8.1 S01 ログイン

- サービス名「Webタイムカプセル」を表示する。
- 写真と同じポーズを再現して開く体験を短く説明する。
- 「Googleでログイン」ボタンを表示する。
- ログイン処理中はボタンを無効化する。
- ポップアップのキャンセルと認証失敗を区別し、再試行できるメッセージを表示する。

### 8.2 S02 フォルダ一覧

- 自分が参加しているフォルダだけをカード表示する。
- カードにはフォルダ名、保存写真枚数、ロック中／この端末で開封中の状態を表示する。
- 「フォルダを作る」ボタン、アカウントメニュー、ログアウトを表示する。
- 0件の場合は、体験説明と作成ボタンを含む空状態を表示する。
- 鍵写真そのものは一覧のサムネイルに使用しない。

### 8.3 S03 フォルダ基本情報

入力項目：

- フォルダ名：必須、1〜40文字、前後の空白を除去
- 参加者メールアドレス：作成者以外を1〜3件

入力時にメール形式、重複、ログイン中メールの重複入力、参加者総数が2〜4人であることを検証する。「作成後はフォルダ名と参加者を変更できない」と次へ進む前に明示する。

### 8.4 S04 鍵写真選択

- 端末の写真ライブラリから1枚選択する。
- 対応形式と容量上限を選択UI付近に表示する。
- 選択直後に形式、容量、画像の破損を検証する。
- EXIFの向きを反映したプレビューを表示する。
- 登録可能な写真が決まるまで別の画像を何度でも選び直せる。

### 8.5 S05 鍵写真確認

- サーバーのRTMPoseによる検出結果を登録可否の基準にする。
- 検出された人数と骨格を画像上に重ねて表示する。
- 検出人数が参加者数と同じで、2〜4人であることを必須とする。
- 各人について、肩幅による正規化と並び順判定が可能でなければならない。
- 鍵写真側で比較する8点のうち6点以上が有効であることを登録条件とする。
- 登録不可の場合は理由を表示し、「別の写真を選ぶ」でS04へ戻す。

主なエラー文例：

- 「3人で登録するフォルダですが、写真では2人を検出しました」
- 「5人以上の写真には対応していません」
- 「肩が見える、全身に近い写真を選んでください」
- 「人物同士が重ならない写真を選んでください」

### 8.6 S06 作成内容確認

フォルダ名、参加者メールアドレス、鍵写真、検出人数、変更不可となる項目を表示する。「この内容で作成」実行後は二重送信を防止し、失敗時は入力内容を保持したまま再試行できるようにする。

### 8.7 S07 ロック中フォルダ

- 写真認証が必要であることと登録人数を表示する。
- 「同じ人である必要はなく、人数・立ち位置・ポーズを合わせる」ことを説明する。
- 「写真認証を始める」ボタンを表示する。
- 鍵写真そのものは認証成功前に表示せず、認証に必要な骨格ガイドだけを使用する。

### 8.8 S08 カメラ事前案内

ブラウザの権限ダイアログを出す前に、写真認証のためにカメラを使用すること、撮影画像は保存写真へ自動保存しないこと、判定後に認証用写真を削除することを説明する。

「カメラを許可して進む」を押した後に権限要求を行う。拒否時はブラウザ設定から許可する方法と再試行ボタンを表示する。

### 8.9 S09 写真認証カメラ

表示要素：

- カメラプレビュー
- 鍵写真から生成した半透明の骨格ガイド
- MediaPipe Tasks Visionで検出した現在の骨格
- 検出人数とポーズ調整メッセージ
- 手動シャッターボタン、キャンセル

動作：

- MediaPipeによる判定は撮影支援専用で、最終合否には使用しない。
- おおむね一致した状態が安定したら3秒カウントダウンして自動撮影する。
- カウントダウン中に人数またはポーズが大きく外れた場合は中止する。
- 自動撮影の条件を満たさなくても手動撮影は常に可能とする。
- プレビューを左右反転する場合も、サーバーへ送る画像または座標は比較方向が一致するよう補正する。
- 撮影後に写真を確認し、「この写真で判定」「撮り直す」を選べる。

### 8.10 S10 判定中

- 撮影画像を圧縮して送信し、サーバーのRTMPose判定を待つ。
- 二重送信を防止する。
- 進行中表示を出し、一定時間応答がなければタイムアウトとして失敗状態へ遷移する。

### 8.11 S11 認証結果

成功時：

- 鍵写真と今回の認証用写真を並べて表示する。
- 「開きました」などの成功メッセージを表示する。
- 短時間後、または「フォルダを見る」でS12へ遷移する。
- 認証用写真の表示は端末上の一時Blobを使用し、画面離脱時に破棄する。

失敗時：

- 人数不足は「あと1人足りないみたい」のように表示する。
- ポーズ違いは「左の人の左ひじをもう少し下に」のように、直す箇所を1つ表示する。
- 点が隠れている場合は方向を推測せず、「左の人の右手首が見えるようにしてね」と表示する。
- 「もう一度撮る」でS09へ戻す。試行回数は無制限とする。

### 8.12 S12 写真一覧

- 保存写真を新しい順のグリッドで表示する。
- 写真追加、複数選択、フォルダ情報への導線を表示する。
- 0件の場合は空状態とアップロードボタンを表示する。
- 署名付きURLの期限切れ時は、有効な認証セッションを使って新しいURLを取得し、可能な限り自動復旧する。
- 認証セッションが期限切れの場合はロック画面へ戻す。

### 8.13 S13 写真詳細

- 1枚を画面内に収まる形で表示する。
- スワイプまたはボタンで前後の写真へ移動できる。
- 撮影日時が利用できる場合は表示し、位置情報は表示しない。
- 削除は確認ダイアログを経由する。

### 8.14 S14 写真選択・削除

- タップで複数選択でき、選択数を表示する。
- 削除前に対象枚数を含む確認を表示する。
- 削除は即時実行し、元に戻す機能は設けない。
- 一部削除に失敗した場合は成功件数と失敗件数を表示し、一覧を再取得する。

### 8.15 S15 写真アップロード

- 1回に最大10枚を選択できる。
- フォルダ内の保存写真は最大20枚とする。
- 形式変換、圧縮、アップロードの進捗を写真ごとに表示する。
- 全体失敗にせず、写真ごとに成功・失敗を表示する。
- 上限を超える選択は送信前に止め、追加できる残り枚数を表示する。

### 8.16 S16 フォルダ情報・削除

フォルダ名、参加者メールアドレス、保存写真枚数と、各設定を変更できないことを表示する。

- 参加者全員がフォルダを削除できる。
- 誤操作防止のため、確認画面でフォルダ名の再入力を必須とする。
- 削除すると鍵写真、保存写真、骨格データ、参加者情報、認証セッションをすべて削除する。
- 実行後は元に戻せない。
- 成功後はS02へ戻し、端末内の当該フォルダ認証情報を破棄する。

## 9. 写真認証仕様

### 9.1 役割分担

| 処理 | 実行場所 | 使用技術 | 用途 |
| --- | --- | --- | --- |
| リアルタイム骨格ガイド | ブラウザ | MediaPipe Tasks Vision JavaScript版 | 構図調整、撮影支援 |
| 最終合否判定 | サーバー | RTMPose | 全ユーザーで一貫した正式判定 |

MediaPipeとRTMPoseで結果が異なる可能性があるため、「ガイドは目安です」と表示し、最終結果は常にサーバー判定を採用する。

### 9.2 判定対象

顔、服装、背景、人物の同一性は判定しない。別人でも人数、立ち位置、ポーズが条件を満たせば認証成功とする。

判定対象は左右のひじ、手首、ひざ、足首の8点とする。関節角度は表示やデバッグ用に計算してもよいが、MVPの合否には使用しない。

### 9.3 人数と並び順

1. 鍵写真と認証用写真の人物数が一致しなければ失敗とする。
2. 人物数は2〜4人とする。
3. 各画像の人物を腰の中心X座標で左から右へ並べる。
4. 腰の中心を求められない人物は、両肩の中心X座標を使用する。
5. 腰と肩のどちらでも並び順を決められない場合は撮り直しとする。
6. 並べた1人目同士、2人目同士を比較する。立ち位置の入れ替えは別ポーズとして扱う。

### 9.4 座標の正規化

人物ごとに両肩の中点を原点、肩幅を1として、各判定点の相対X・Y座標を求める。これにより、カメラとの距離や画像内の人物サイズの差を吸収する。

両肩が有効でない、または肩幅が極端に小さい場合は、その人物を判定不能として撮り直しを求める。

### 9.5 点の有効条件と欠損

RTMPoseの信頼度が0.5以上で、推定座標が画像内にある点だけを有効とする。

- 鍵写真で無効だった点は比較対象から除外する。
- 鍵写真は1人あたり比較可能な点が6点以上あることを登録条件とする。
- 認証用写真で比較点が隠れた場合、1人あたり2点までは許容し、欠損1点につき正規化距離0.5を平均との差分へ加える。
- 1人あたり3点以上が欠損した場合は「体が見えない」として失敗にする。

### 9.6 合否

各人について比較対象点のユークリッド距離を求め、認証用写真で欠損した点には距離0.5を使用する。次の両方を満たす場合、その人物を成功とする。

- 全比較対象点の距離の平均が0.35以下
- 欠損でない各点の距離がすべて1.0未満

参加者全員が成功した場合に限り、フォルダの写真認証を成功とする。設定値は定数化し、検証結果に応じて変更可能にする。

| 設定 | 初期値 |
| --- | ---: |
| 最大人数 | 4 |
| 点の信頼度 | 0.5 |
| 鍵写真の最低有効点数／人 | 6 |
| 認証用写真の許容欠損点数／人 | 2 |
| 欠損点ペナルティ | 0.5 |
| 平均距離しきい値 | 0.35 |
| 単一点距離しきい値 | 1.0 |

### 9.7 失敗フィードバック

人数が一致しない場合は人数を最優先で案内する。人数が一致している場合は、平均との差分が最も大きい人物の、最もずれた有効点を1つ案内する。

方向は鍵写真の位置へ戻す向きとして、上、下、外側、内側のいずれかに変換する。左右は撮影される人物基準で表現し、画面内に簡単な図示を併用する。

## 10. 認証セッション

- 認証状態はフォルダごとに独立する。
- 初回アクセス時、または認証セッションが無効な場合に写真認証を求める。
- 認証成功時に、サーバーは最長12時間有効なフォルダ閲覧トークンを発行する。
- フロントエンドはトークンを sessionStorage へ保存し、localStorage には保存しない。
- 画面更新、一覧へ戻って同じフォルダを開き直す操作、一時的な通信切断だけでは再ロックしない。
- タブまたはブラウザを閉じた場合、ログアウトした場合、12時間が経過した場合は再認証を求める。
- サーバーはすべての保護APIで有効期限とフォルダを検証する。
- フォルダ削除時は関連する認証セッションをすべて無効化する。

Webブラウザでは通信が切れた瞬間を常に正確に検知できないため、「接続が切れるまで」は上記のタブ／ブラウザセッションとサーバー有効期限で実現する。

## 11. 画像仕様

### 11.1 対応形式と入力制約

- 入力対応：JPEG、PNG、WebP、HEIC、HEIF
- 対応外：GIF、SVG、RAW、動画
- 元ファイルの上限：1枚15MB
- EXIF Orientationを反映する。
- 保存時にEXIFを除去し、GPSなどの位置情報を残さない。
- HEIC／HEIFはJPEGへ変換する。変換に失敗した場合は対応形式への変換を案内する。
- MIMEタイプ、拡張子、ファイルサイズ、画像としてデコード可能かをフロントとバックエンドの両方で検証する。

### 11.2 保存用の正規化

| 種類 | 保存形式 | 長辺 | 品質 | 目標容量 |
| --- | --- | ---: | ---: | ---: |
| 鍵写真 | JPEG | 1920px | 約85% | 2MB以下 |
| 保存写真 | JPEG | 1920px | 約85% | 2MB以下 |
| 認証用写真 | JPEG | 1280px | 約80% | 1MB以下 |

圧縮後も目標容量を超える場合は品質を段階的に下げる。バックエンドの受入上限を超える場合は送信せずエラーを表示する。

### 11.3 枚数

- 鍵写真：フォルダにつき1枚
- 保存写真：フォルダにつき最大20枚
- 1回のアップロード：最大10枚
- 認証用写真：1回の試行につき1枚、一時利用のみ

### 11.4 認証用写真の破棄

- 端末上では比較表示に必要な間だけBlob／Object URLを保持し、画面離脱時に解放する。
- サーバーへ送った原画像は判定完了後、成功・失敗にかかわらず削除する。
- 異常終了時の削除漏れに備え、一時ストレージへ1日のライフサイクル削除を設定する。
- 認証用写真を保存写真へ自動追加しない。

## 12. 写真配信と署名付きURL

- 鍵写真と保存写真を置くストレージは非公開とする。
- 参加者権限と認証セッションの検証後に、バックエンドから署名付きGET URLを取得する。
- 署名付きURLの有効期限は5分を初期値とする。
- URLが切れても認証セッションが有効なら、新しいURLを取得して表示を再開する。
- 署名付きURLをアプリログ、解析イベント、エラーメッセージへ記録しない。

## 13. バックエンド連携で必要な情報

具体的なパスやHTTP方式はAPI設計時に確定するが、少なくとも次の操作とレスポンス情報を必要とする。

| 操作 | 必要な主なレスポンス |
| --- | --- |
| ログインユーザー取得 | ユーザーID、表示名、確認済みメールアドレス |
| 参加中フォルダ一覧 | ID、名前、写真枚数、認証セッション状態 |
| 鍵写真検証 | 検出人数、人物別骨格、登録可否、不可理由 |
| フォルダ作成 | フォルダID |
| 認証用ガイド取得 | 人数、正規化済み骨格データ。鍵写真原本は返さない |
| 写真認証 | 成否、閲覧トークン、有効期限、失敗種別、修正対象人物・点・方向 |
| 保存写真一覧 | 写真ID、表示用URL、撮影日時、登録日時 |
| アップロード | 写真ごとの成否、写真ID、失敗理由 |
| 写真削除 | 写真ごとの成否 |
| フォルダ削除 | 完了状態 |

エラーは画面で分岐できる安定したコードを返す。ユーザー向け日本語文言は原則フロントエンドで管理する。

## 14. エラー・例外状態

最低限、次の状態を個別に扱う。

- Googleログインのキャンセル、失敗
- フォルダ一覧の取得失敗、0件
- 鍵写真の形式・容量不正、破損
- 鍵写真で人物を検出できない、人数不一致、5人以上
- 肩を検出できない、有効点不足、人物の重なり
- カメラ非対応、権限拒否、他アプリによる使用中
- 認証用写真の送信失敗、判定タイムアウト
- 認証失敗、人数不足、点の欠損、ポーズ違い
- オフライン、一時的な通信切断、再接続
- 認証セッション期限切れ
- 署名付きURL期限切れ、再発行失敗
- HEIC／HEIF変換失敗
- 保存写真の枚数超過
- 複数アップロード、複数削除の一部失敗
- フォルダが別参加者により削除済み

再試行可能なエラーでは入力や選択状態を可能な限り保持する。通信失敗と写真認証の不一致を同じ文言にしない。

## 15. UX・アクセシビリティ

- スマートフォンの片手操作を想定し、主要ボタンを画面下部へ配置する。
- タップ領域は原則44px四方以上とする。
- セーフエリアを考慮する。
- 縦向きを基本とし、横向きでも操作不能にしない。
- ローディング中、空状態、失敗状態を必ず用意する。
- 成否を色だけで表現せず、文言とアイコンを併用する。
- 骨格ガイドと説明文のコントラストを確保する。
- 削除や変更不可の項目は実行前に明示する。
- 判定文言は責める表現を避け、「あと少し」など再試行しやすい表現にする。

## 16. セキュリティ・プライバシー

- 参加者判定と認証セッション検証は必ずバックエンドで行う。
- ブラウザで計算した骨格や合否を最終結果として信用しない。
- ストレージを公開設定にしない。
- 認証トークンをURLへ含めない。
- 鍵写真、認証用写真、署名付きURLをログへ出さない。
- 認証用写真を判定後に削除する。
- フォルダ削除時は鍵写真、保存写真、骨格データ、参加者情報、認証セッションを一括削除する。
- 写真認証は本人確認ではないことを、ユーザーに誤認させない。

## 17. 受入条件

### 17.1 フォルダ作成

- 作成者を含む2〜4人のメールアドレスと鍵写真1枚でフォルダを作成できる。
- 参加者数と鍵写真の検出人数が異なる場合は作成できない。
- 登録に失敗した鍵写真を別の画像へ選び直せる。
- 作成後、フォルダ名、鍵写真、参加者を変更できない。
- 未利用ユーザーのメールアドレスを登録しても作成でき、後日同じGoogleメールでログインすると一覧へ表示される。

### 17.2 写真認証

- 未認証の参加者がフォルダを開くと写真認証へ進む。
- MediaPipeのガイドを見ながら手動または自動で撮影できる。
- サーバーのRTMPose判定で、人数、並び順、8点の距離を使って合否を決める。
- 別人でも条件を満たせば成功する。
- 失敗時に人数または直すべき部位を表示し、回数制限なく再撮影できる。
- 成功時に鍵写真と今回の写真を一時的に並べて表示できる。
- 認証用写真が保存写真や履歴へ自動保存されない。

### 17.3 認証後

- 画面更新だけでは再ロックされない。
- 同じタブで一覧へ戻り、同じフォルダを開き直しても再認証を求めない。
- 一時的な通信切断後も、12時間以内の有効なセッションで復帰できる。
- タブ／ブラウザを閉じた後、ログアウト後、または12時間経過後は再認証が必要になる。
- 他フォルダの認証状態は共有されない。

### 17.4 写真管理

- 対応形式の写真を1回10枚、フォルダ合計20枚まで追加できる。
- 写真を一覧・詳細で閲覧できる。
- 参加者なら誰でも保存写真を削除でき、元に戻せない。
- 参加者なら誰でも確認後にフォルダを削除でき、関連データがすべて削除される。

## 18. 実装前後に調整可能な項目

以下はプロダクト仕様を止める未決事項ではなく、実装や実機検証で調整する項目である。

- 画面の最終ビジュアル、配色、ロゴ
- 文言の最終調整
- 自動撮影を開始するMediaPipe側の安定時間と目安しきい値
- RTMPoseの初期しきい値と欠損ペナルティの追加実機検証
- APIのパス、HTTP方式、エラーコード名
- 対象ブラウザの最終範囲

判定しきい値を変更する場合は、同じポーズ、異なるポーズ、2〜4人、点の隠れ、端末差を含む検証結果を記録する。
